# 前端交互系统审查与验收

适用范围：管理员与家属入口，基于 PR #124 候选代码。每次验收应记录候选 SHA、浏览器/WebView2 版本、视口大小和复现实例，不以 CSS 规则的存在代替实机结果。

## 已审查并修正的边界

| 维度 | 风险与本轮处理 | 最小验收 |
| --- | --- | --- |
| 导航层级 | 管理端侧栏曾通过路由 `key` 重建菜单，导致焦点丢失和无用重渲染；现在保持组件实例，展开当前路径所属分组。管理端与家属侧栏使用 `nav` 地标 | 键盘 Tab 浏览菜单，进入子页后菜单不重建，当前分组可见 |
| 页面焦点 | 管理端、家属端以前只重置滚动位置；现在仅在 `route.path` 改变时，将焦点置于带 `tabindex=-1` 的主内容，不因查询参数变化抢焦点 | 键盘触发导航后，焦点进入主内容；查询筛选、翻页时输入焦点不被抢走 |
| 表单一致性 | 老人和监护人表单改为顶置标签，电话使用 `inputmode=tel`；删除一个隐藏且错误标成“年龄”的旧 ID 表单项。设备绑定码采用适合窄屏的数字键盘与布局 | 手机软键盘、验证提示和屏幕阅读器标签正常；没有误导性可编辑字段 |
| 移动端操作 | 320–360px 头部压缩避免操作溢出；绑定码表格在窄屏可横向滚动并可键盘聚焦 | 320/360/390/768px，200% 字号；按钮可见可点，无页面级水平溢出 |
| 长时间视觉稳定 | 移除侧栏反复销毁；手动/系统减少动画覆盖 `body` 下的传送弹窗、提示与遮罩，避免仅主应用生效 | 持续切换页面/弹窗、反复调整字号与动画偏好，观察焦点、内存和布局抖动 |

## 仍需实机验收

1. **导航**：分别用键盘、鼠标与触摸，覆盖管理端全分组、家属端底部导航、Tab 关闭后重定向、浏览器前进/后退、未授权跳转。检查主区域只有一个可识别地标，页面标题与实际路由一致。
2. **表单**：覆盖老人档案、监护人、绑定码、设备登记、登录和 MFA；验证错误就地呈现、回车无重复写入、取消后焦点合理恢复以及网络错误不静默丢失输入。
3. **移动端**：320px、360px、390px、768px；放大字号、纵横屏和虚拟键盘出现后的可见操作区域；滚动表格不可遮住“作废”按钮，弹窗关闭入口保持触达。
4. **持续运行**：Windows WebView2 实际环境运行至少 60 分钟，管理端与家属端各循环导航 100 次、设备/告警弹窗各开关 100 次、地图开关 100 次。记录 JS 堆、detached DOM、RAF、ResizeObserver、事件监听、工作集和交互帧时间；关闭后空闲再采样。
5. **验收方法**：必要 CI 门禁（Vitest、vue-tsc、构建、UI Quality、Security、Desktop Contract）必须在确切 HEAD 成功。若实机发现焦点顺序、外链确认、弹窗遮挡或内存持续增长，先查原始日志与堆快照再定位修复。

现有体验修改没有实测的 FPS、CLS、INP 或 WCAG 合规证明；此文档是验收矩阵，不是“全部验收通过”证明。
