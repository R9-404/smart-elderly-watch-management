# 健康同步及统计副本保护

迁移 0041 为健康变化流、最新样本和日统计结果增加密文列。

| 表 | 认证范围 | 保留的查询字段 |
| --- | --- | --- |
| `health_change` | 版本、住养老人 ID、样本 ID | 归属与同步游标 |
| `health_sample_latest` | 住养老人 ID、序列键、版本 | 归属、序列和版本 |
| `metric_daily` | 缓存键、计算版本 | 时间窗口、归属、状态和计算版本 |

配置数据密钥后的写入在业务事务中封装载荷，旧载荷列置为 SQL NULL。授权读取先验证归属，再读取需要的载荷。缺少 reader、认证失败及不同记录之间的密文互换都会导致读取失败。新旧载荷可在上线和回填期间并存。回退 SQL 保留数据列，回退到旧应用前须使用匹配的备份恢复。

## 回填及轮换

在后端模块目录构建 `go build -o protect-health-projections ./cmd/protect-health-projections`，使用受限的 `MYSQL_DSN_FILE` 和 `DATA_ENCRYPTION_KEY_FILE` 注入实际部署的值。默认模式扫描待处理行数并验证各表首条现有密文。

执行前停止相关写入端，验证匹配的备份可恢复，并以 `rekey-data` 的只读模式核对所有现存密文及 reader。每次显式执行 `protect-health-projections --apply --limit 100` 会在三表合计迁移至多指定的行数，允许范围 1–1000。每条在行锁内重读并写入，原同步游标、缓存版本与业务字段保持原值。部分完成返回非零和剩余行数，重跑接续迁移。留存最终扫描的三表剩余量和 `rekey-data` 的全量报告。

三列纳入现有 `rekey-data` 的预检、CAS 重封装和认证复查。旧备份仍使用其匹配的密钥，最终密钥撤销由资产盘点与恢复验收决定。
