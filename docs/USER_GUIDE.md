# 岁宁 2.1.0 使用指南

适用于 Windows 桌面端及通过浏览器访问的岁宁平台。按当前 `preview` 功能编写；正式发布时以对应安装包中的版本说明和 `release-manifest.json` 为准。

## 1. 首次使用

1. 从项目 [GitHub Releases](https://github.com/WatchTestCs/smart-elderly-watch-management/releases) 下载与系统架构对应的安装包。Windows 可使用 Setup；Portable 必须完整解压，保留 `suining.exe` 与 `suining-server.exe`。按同一发布批次的 `SHA256SUMS.txt` 核对下载文件。
2. 由部署人员准备独立的 MySQL 业务库和持久化的数据加密密钥。PostgreSQL 用于异步分析，不是日常业务的必要前置条件。数据库连接、备份和旧库迁移参见 [双库配置](DUAL_DATABASES.md) 与 [备份恢复](runbooks/backup-restore.md)。
3. 启动桌面应用。首次安装按初始化界面创建管理员。**系统没有默认管理员账号或通用密码**。若提示数据库未连接，先检查服务与配置，不要重复初始化。
4. 管理员登录后建立老人档案，补齐必要的监护人和家属关联，再到设备管理登记手表并完成绑定。
5. 配置监测阈值，确认手表已认证、绑定版本正确并能上报数据。使用真实设备前按 [手表接入](WATCH_INTEGRATION.md) 完成端侧配置。
6. 在运营工作台查看健康、位置、告警与照护任务；家属使用邀请码注册，仅查看已关联长者的信息。

**重要：** 桌面窗口关闭后，本地服务也会停止。需要全天候接收 SOS 的机构必须部署独立常驻服务和人工值守流程，详见 [照护服务部署](CARE_SERVICE_DEPLOYMENT.md)。

## 2. 功能与入口

| 角色与入口 | 功能 | 使用要点 |
| --- | --- | --- |
| 首次初始化 `/setup` | 创建首位管理员 | MySQL 正常且完成迁移后操作；保管凭据 |
| 管理端 · 运营总览 | 日常工作与告警概览 | 先确认数据源与设备在线状态 |
| 管理端 · 老人档案、监护人信息 | 老人和关系档案 | 先核对关联关系，再登记设备 |
| 管理端 · 设备管理 | 登记、绑定、解绑、设备密钥、绑定码与告警 | 换绑后检查绑定版本；不要在不确定请求结果时重复生成绑定码 |
| 管理端 · 心率与血压、睡眠与步数、生活信息 | 读取设备上报的记录 | 关注采样时间、来源和缺失状态，不把没有上报当成正常 |
| 管理端 · 位置与告警 | 查看最后位置与异常信息 | 历史位置和未知精度不得视为实时定位 |
| 管理端 · 监测阈值档案 | 管理告警阈值 | 修改前确认关联设备和受影响老人 |
| 照护协作 · 工单 | 接单、开始、处置、复核 | 处置后仍需独立复核；界面确认不能代替实际到场 |
| 管理端 · 家属账号、邀请码 | 管理家属关联和注册 | 邀请码属于受限凭据，不要公开分享 |
| 管理端 · 公告、评论 | 发布通知和管理反馈 | 核对发布对象及可见范围 |
| 家属端 · 首页、健康、活动、位置、公告、个人中心 | 查看已关联亲属的资料 | 无权限时联系机构核对账号绑定 |
| 页面顶部 · 大字 | 切换字号 | 浏览器禁止存储时仅对当前页面会话有效 |

护理员、审计员及主管的功能范围由服务器端岗位权限决定。账号即使看到旧的菜单或页面，也不能据此认定具有操作权限。

## 外部链接与网页安全

Windows 桌面端点击外部网页链接时，岁宁会显示**完整目标网址与域名**，用户可选择“打开网站”或“留在岁宁”。确认后使用系统浏览器打开，照护工作台本身不会导航至第三方站点。普通左键、Ctrl/Shift 点击以及鼠标中键均受到同样的确认流程保护。

- **默认拒绝**非 HTTPS、携带 URL 用户名/密码、IP 地址、本地主机地址及常见广告重定向域名。网页内嵌地图使用受限 iframe，不授予其打开弹窗或跳转顶层页面的权限。
- **允许用户决定**打开正常的 HTTPS 站点，包括地图提供商和帮助文档；不使用“禁止所有外部链接”的策略。
- **防护边界**：广告拦截域名列表无法覆盖所有广告或恶意重定向。系统浏览器会执行 HTTPS 证书验证，但 DNS 污染、受信任证书被滥用和目标站点自行重定向不能仅靠应用内确认完全消除。应保持系统与浏览器更新，并使用可信网络及 DNS 解析服务。
- 当前提供的是用户确认、协议/目标校验与地图沙箱隔离；任何新外部链接都应采用标准 `a[href]`，不要在业务组件中绕过统一确认流程。

## 常规设置与地图服务

登录后点击页面顶部 **设置**，管理员与家属使用同一套本机显示偏好：

- **大字模式**：即时调整字号；顶部“大字/标准字”快捷入口继续可用。
- **减少界面动画**：适用于低性能设备或易受动画影响的使用者，立即生效。
- **默认地图**：高德地图（免 Key iframe）、腾讯地图（官方链接新窗口打开）、Google 地图（官方 Maps URLs，免 Key）、仅本地标记（无第三方网络请求）。
- **高德为新用户默认项**：已有用户明确选择的其他地图偏好不被覆盖；点击加载后切换长者的位置记录，地图持续显示并自动切换到新坐标。默认仍由用户主动加载，避免无意泄露位置信息或增加启动时的网络开销。
- **高德地图类型**：标准地图 / 卫星图。
- **设备上报坐标系**：WGS84 或 GCJ-02，默认 WGS84；选择 GCJ-02 时不再重复偏移。仅在明确设备规格或接入配置后修改。
- **选中位置后自动加载**：默认关闭。开启后高德地图会在位置记录可用时自动加载，向地图服务商发送所选坐标。涉及敏感位置时建议保持默认关闭。
- **恢复默认设置**：重置地图与动画偏好；不清除账号、健康数据或服务器配置。

设置仅存储在本机浏览器/WebView2 的 `localStorage` 中，不需要数据库迁移。禁用本地存储时只在当前会话内生效。任何地图外部服务都只传送坐标和通用位置标记，不传送被照护者姓名。

**Google 地图免费接入：** 设置默认地图为“Google 地图”后，在位置页点击 **在 Google 地图查看位置**，先确认外部链接，再通过系统浏览器打开官方 `https://www.google.com/maps/search/?api=1&query=纬度,经度`。不需要 Google API Key、SDK 或云端计费配置，也不向 Google 传送老人姓名。Google 地图在中国大陆部分网络环境不可访问；请切换回高德或离线标记。若设备上报坐标为 GCJ-02，打开 Google 前会将显示用坐标逆向转换至 WGS84，不修改数据库原始记录。官方文档：[Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)。

Google 官方 [Maps Embed API](https://developers.google.com/maps/documentation/embed/quickstart) 也是免费使用，但**要求 API Key 及开通结算账号**，因此与当前免 Key 的外链方案分离，未将密钥放入本地偏好或前端源码。

**扩展其他地图**：当前地图提供者的类型与 URL 生成统一由 `frontend/src/utils/mapProviders.ts` 管理。新增受支持地图时，在此处增加明确枚举与经过审核的官方接口和坐标转换规则；不要让用户输入任意 iframe 地址。腾讯地图目前使用 URI 地点标记链接，**不属于内嵌地图或 Key SDK**。在 Windows 桌面端通过只允许官方地图域名的受限命令调用系统浏览器，不允许设置任意网址。需要多点、轨迹与实时标记的腾讯/高德 SDK 应单独接入、核对授权与密钥保护后开放。

## 地图使用（中国大陆）

- 默认仅显示设备原始经纬度与本地标记；点击**加载高德地图**后，才通过高德官方免 Key 嵌入页获取在线底图。离开地图或点击**关闭在线地图**会卸载嵌入页。
- 在线地图提供可拖动、可缩放的单点地图。若桌面 WebView2 或站点安全策略阻止 iframe，可使用**在高德地图中打开**。
- 地图标记按照设备上传坐标为 **WGS84** 进行 WGS84 → GCJ-02 显示转换。若设备上报已使用 GCJ-02，应在设备接入时统一并标明坐标系，避免重复偏移。存储值不做修改。
- 在线服务会接收被选中记录的经纬度；只有用户主动加载时才向高德发送请求。不发送老人姓名，且不得把地图底图解释为设备实时在线或经纬度精度已核验。
- 免 Key 官方 iframe 不支持自由定制实时轨迹、多点图层或复杂标记。若后续需要这些能力，可作为单独增强接入高德或腾讯 JS SDK，并由部署者自行配置对应 Key，**不将 Key 写入源码**。
- 官方服务说明：[高德单地点嵌入](https://developer.amap.com/api/uri-api/guide/embedded-map/single-location)、[免 Key 嵌入概述](https://developer.amap.com/api/uri-api/guide/embedded-map/summarize)。

## 3. 常见问题与解决清单

| 现象 | 首先检查 | 处理方法 |
| --- | --- | --- |
| 界面显示“数据库未连接” | MySQL 是否运行、DSN、库名和迁移状态 | 修复配置后重启服务；不要反复执行初始化或对真实业务库直接重建 |
| 登录失败、提示初始化 | 用户身份、账号状态、数据库与会话配置 | 核对登录凭据及管理员初始化状态；不要寻找默认密码 |
| PostgreSQL 不可用 | 分析服务状态、MySQL Outbox 积压 | 核心业务仍以 MySQL 为准；恢复分析服务后观察积压消退 |
| 安装后无法启动 | WebView2、Windows 版本与完整安装日志 | 检查 WebView2；Portable 必须完整解压并保留 sidecar |
| Windows 提示未知发布者 | 是否来自官方发布页、SHA-256 是否匹配 | 校验来源和清单后再决定是否运行；本地自签名不等于其他设备信任 |
| 设备离线或数据不更新 | 网络、设备认证、绑定版本、最后上报时间 | 先恢复连接；换绑后在手表端重新认证，不要把旧绑定采样归到新老人 |
| SOS 发送后没有看到通知 | 事件工单、通知状态、网关和人工值守 | **先核对是否已生成工单**；超时响应不能直接断定未处理，避免重复派单 |
| 健康值与预期不同 | 来源、语义、采样时间、阈值、设备时钟 | 核对原始记录；勿把历史、缺失或不同设备的采样强行合并 |
| 位置显示旧时间或精度未知 | 时间戳、定位来源、设备是否在线 | 保留位置不确定性，不以历史位置指导紧急搜寻 |
| 创建或作废绑定码后界面未刷新 | 当前选中的老人、设备及操作结果 | 关闭并重新打开对应绑定弹窗，核对服务器返回的现有绑定码；不要盲目重试写入 |
| 出现“岗位无此操作权限” | 当前账号岗位、账号状态 | 请主管检查岗位分配；不要通过刷新页面绕过权限 |
| 保存请求超时或断网 | 服务器端是否已提交 | **先查询实际记录**，确认未写入后再操作；不要连续点击提交 |
| 页面加载失败或更新后白屏 | 资源版本、网络、浏览器缓存 | 先刷新一次；持续失败时记录版本与错误信息提交 Issue |
| 退出登录后仍有旧界面标签 | 当前登录身份与会话 | 重新登录并核对账户；涉及敏感数据时停止继续操作并向管理员反馈 |

## 4. 每次操作前后的检查清单

- [ ] 明确当前角色与目标老人，确认操作对象及绑定关系。
- [ ] 确认业务数据库可用，设备在线状态和最近上报时间可信。
- [ ] 删除、解绑、重置密钥、处置告警前核对影响范围。
- [ ] 写入超时后先核对服务器记录，不直接重复提交。
- [ ] SOS 或摔倒告警由真人确认处置，结案保留独立复核与事件记录。
- [ ] 维护人员定期备份 MySQL、上传图片和密钥备份，并验证恢复流程。

## 5. 提交问题与已知限制

**报告问题时提供：** 应用版本或 Git SHA、操作系统、角色、重现步骤、预期/实际结果、是否复现、数据库是否就绪，以及脱敏后的截图或日志。请勿上传密码、设备密钥、真实健康或位置信息。通过 [GitHub Issues](https://github.com/WatchTestCs/smart-elderly-watch-management/issues) 提交；安全问题使用 [私密安全报告](../.github/SECURITY.md)。

**当前验收边界：** CI 的编译和无界面启动检查不等于真实手表、短信网关、Windows 10 实机、缺失 WebView2 时的联网补装、生产库迁移或长期 SOS 送达测试。完整上线前需要机构独立验收。发布门禁状态见 [发行治理](reliability/release-governance.md)。
