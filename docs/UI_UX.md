# 界面与验收规范

## 可读性与布局

- 主要按钮、导航和提交目标 ≥48×48px；辅助操作 ≥44×44px，按实际点击区域计算。危险操作与普通操作保留间距。
- 正文 ≥16px，标题、关键数据和辅助文字层级清楚。大字模式放大正文和控件，不隐藏字段、截断标签或丢失操作。
- 窄屏表格转为卡片、堆叠或折叠次要信息，始终显示对象名称、状态及操作入口。对话框可滚动，确认按钮可达。
- 导航匹配角色，当前项有选中态，页面标题与业务术语一致，返回与关闭行为可预测。

| 验收模式 | 视口 |
| --- | --- |
| 桌面 | 1440×1000、1360×900 |
| 小屏桌面 | 1024×768 |
| 家属窄屏 | 390×844 |
| 最小窗口 | 360×560 |
| 大字模式 | 1360×900、390×844 |

## 状态与健康数据

- 每个核心页面覆盖加载、空数据、错误、正常、长内容和危险操作确认；空状态与错误给出下一步。
- 网络失败不能显示成“暂无数据”；保留旧数据时标明可能过期。
- 状态使用文字或图标辅助颜色，区分离线、未知和无新记录。
- 健康数据标明最近成功上报时间和过期状态；未上报不能显示为正常，设备读数和超阈值提示不能写成疾病诊断。

## 表单与危险操作

- 输入有可见标签，placeholder 不替代标签。字段错误靠近字段，整体错误使用 `role=alert` 或等效语义，并给出可执行的恢复方式。
- 手机号、密码使用正确的 `autocomplete` / `inputmode`；密码显示按钮有可访问名称和 pressed 状态。提交期间防止重复提交。
- 删除、解绑等确认说明对象、后果和可恢复性；确认按钮使用具体动词，危险按钮与安全操作的视觉权重有区别。

## 键盘与辅助技术

- 所有鼠标操作可用键盘完成，Tab 顺序匹配任务顺序，不用正 `tabindex` 重排；`:focus-visible` 清晰。
- 对话框打开时移入焦点，关闭后归还触发元素；Escape 可能丢失输入时先确认。
- 图标辅助语义，纯图标按钮有 `aria-label`；信息图片提供描述，装饰图片使用空 `alt` 或 `aria-hidden`。保留已验收且语义清楚的图标。
- 动效仅用于层级与状态变化，尊重 `prefers-reduced-motion`；测试截图关闭或固定非确定性动画。

## 样式维护

共享颜色、字号、间距、圆角、阴影、动效、焦点与状态值使用统一 token。Element Plus 覆盖、无障碍规则和页面布局分别维护；不为单页建立另一套设计系统，不一次性重写 `commercial.css`。结构重构与视觉改动分开提交。

## 验收与视觉基线

[UI Quality](../.github/workflows/ui-quality.yml) 使用生产构建检查控件与标题的可访问名称、可见交互目标 ≥44px、普通及大字移动布局，并与 [登录基线](screenshots/login-desktop.png) 比较、上传截图。粗粒度 RMSE 只检测明显布局或资源回归，仍需人工视觉检查。

只有预期视觉改动、目标视口人工确认、无障碍与交互无回退且 PR 说明原因时，才更新基线。不得自动接受截图、覆盖失败基线或放宽阈值掩盖回归；同时变更结构与基线须提供前后对照。

新增流程使用固定测试数据，覆盖桌面、窄屏、大字和键盘操作；模拟 API 不替代真实后端、通知或设备验收。测试入口见 [测试指南](TESTING.md)。
