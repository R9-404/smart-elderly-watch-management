# ADR-0006：Tauri / Go / MySQL 主库与 PostgreSQL 分析库

- Status: Accepted
- Date: 2026-10-18

## Context

桌面客户端、业务服务和数据库需要保持明确的进程与故障边界。界面应能在数据库暂不可用时启动并提示状态；业务数据必须有唯一权威主库，分析存储故障不能阻断核心照护流程。

## Decision

- Windows 桌面壳使用 Tauri 2 / Rust，负责窗口、安全边界、Go sidecar 生命周期和受限初始化 IPC。
- Vue 3 / Vite 前端通过同源 HTTP 调用 Go API，不直接连接数据库，也不持有数据库凭据或桌面初始化令牌。
- Go 服务负责业务 API、设备鉴权、会话、CSRF、数据库迁移、照护作业和静态资源服务。
- MySQL 是唯一业务主库，保存业务事务、会话及分析 outbox。
- PostgreSQL 是可选分析副库，只保存可由 MySQL 重新投影的分析数据；其不可用不应阻断核心业务读写。
- 旧 PostgreSQL 业务库只能通过独立、显式的离线预检查与导入工具迁移到空 MySQL 目标库；安装程序不自动迁移业务数据或本地图片。

## Consequences

- MySQL 的迁移、备份、恢复与加密密钥管理属于核心运维要求。
- PostgreSQL 分析投影允许幂等重试与恢复回填，但不能作为业务事务的回退主库。
- 桌面端关闭时会结束本地 Go sidecar；需要全天候接收手表上报和 SOS 的部署必须运行独立常驻服务。
- 网关接受通知不等于实际送达；送达回执和现场照护处置必须分别确认。
- 当前支持的桌面交付目标为 Windows x64；其他平台需独立构建与验收。
